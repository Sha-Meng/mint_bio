## User Requirements
- 希望建设内容管理后台，脱离当前手工 JSON 编辑方式。
- 希望图片、视频等资源不再依赖前端工程打包与重新编译。
- 当前已具备腾讯云服务器、CDN、域名，希望尽量复用现有基础设施。
- 明确不希望为后台能力引入新的订阅型 SaaS 成本。
- 后续主要由不懂技术的运营维护，需要浏览器即可操作、无本地环境依赖。
- 对未来的平台化扩展要求不高，新闻复杂度不会很高。
- 当前生产环境由宝塔面板管理现有网站部署与 MySQL。
- 已确认采用最低可行版：`Directus + 现有腾讯云服务器/数据库 + 工程外媒体目录 + 现有 CDN`。
- 希望后续迁移工作可被长期分阶段执行，并持续记录执行进度。


## Product Overview
- 当前项目是 Vue CLI 的官网前端，新闻模块通过运行时读取 `public/data/news*.json` 展示内容。
- 新闻图片主要来自 `src/assets/News/*` 打包资源，导致新增图片时仍需重新构建前端。
- 当前没有独立 CMS / DAM / 内容工作流，编辑方式偏工程化，不适合高频运营更新。
- 当前阶段重点从“长期平台上限”转为“低成本、低运维、运营易用、快速落地”。

## Core Features
- 新闻内容建模与管理
- 图片视频上传、托管、分发
- 草稿 / 发布工作流
- 浏览器内可操作的后台界面
- 与现有前端新闻页面平滑集成
- 内容迁移与回滚能力

## Tech Stack Selection
- 前端保持 Vue 站点不变，优先做增量式后端接入
- CMS 采用：`Directus` 自建
- 数据库优先复用现有 `MySQL / PostgreSQL`
- 媒体层采用：`Directus 本地存储（外部目录） + 现有 CDN`
- 内容通过运行时 API 获取，避免每次内容更新重新构建
- 推荐读接口增加一层轻量 BFF / 现有后端适配，降低前端对 Directus schema 的直接耦合

## Implementation Approach
- 优先复用现有腾讯云服务器、CDN、域名，避免引入新的订阅型服务。
- 后台选择自托管、浏览器可用、对运营友好的开源 CMS。
- 媒体资源从“工程内打包”迁移到“Directus 外部存储目录 + CDN 缓存访问”。
- 内容模型以轻量结构化为主：少量集合 + 受控区块 JSON，不做重型 page builder。
- 通过分阶段切换完成上线：基础设施 -> CMS 模型 -> 迁移脚本 -> 前端接入 -> 联调验收 -> 切流。

## Implementation Notes
- 本次任务以实施蓝图为主，不直接修改业务代码。
- 方案需要兼顾：零订阅、运营可用、低技术门槛、低复杂度、低后续运维负担。
- 鉴于当前新闻规模仅数十条，历史数据建议一次性完整迁移，而不是长期双轨维护。

## Architecture Design
- 内容后台：`Directus` 提供新闻、分类、文件管理、权限与发布状态
- 数据库：复用现有数据库中的独立 schema / database，不与业务主表混用命名
- 媒体层：Directus 使用本地存储适配器，文件物理落盘到工程外目录，例如 `/data/mintbio/directus/uploads`
- 访问层：CDN 加速 `cms` 站点的 `/assets/*` 或独立媒体子域，官网通过固定媒体域名访问资源
- 读接口：优先由现有后端提供 `/api/news/*` 适配接口，统一屏蔽 Directus 内部结构
- 运维层：补充 HTTPS、角色权限、数据库备份、上传目录备份、缓存刷新与磁盘监控

## Directory Structure
- 当前分析基于 `src/pages/MiNTNews*`、`src/components/MiNTNews/*`、`public/data/*`、`src/assets/News/*`
- 本次输出产物将写入 artifact 报告，不改动现有业务目录
- 目标服务器目录建议：
  - `/srv/mintbio/directus/`
  - `/data/mintbio/directus/uploads/`
  - `/data/backup/mintbio/directus/`

## Key Code Structures
- 当前新闻列表来自 `news_list.json`
- 当前新闻详情来自 `news_{id}.json`
- 当前图片通过 `require(@/...)` 打包引用
- 目标改造后内容来源改为 API，媒体来源改为 Directus 资产 URL / CDN URL
- 首页最新新闻、新闻列表、新闻详情都应统一切到同一套后端内容源
