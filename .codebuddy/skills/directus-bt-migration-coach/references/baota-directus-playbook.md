## 宝塔环境下 Directus 迁移执行参考

### 1. 适用前提
- 服务器已安装宝塔面板
- 现有官网已在宝塔内管理站点
- 已有 MySQL 可复用
- 已有域名和 CDN
- 当前目标是新闻模块最低可行版迁移，不做大型内容平台

### 2. 宝塔对方案的影响
宝塔不会改变总体路线，但会改变具体落地方式：

- **站点管理**：优先通过宝塔创建 `cms` 子站点或反代配置
- **Nginx 配置**：优先通过宝塔站点配置追加反向代理和缓存规则
- **数据库管理**：优先通过宝塔创建或管理 CMS 独立数据库
- **SSL**：优先通过宝塔申请和续签证书
- **文件目录**：上传目录应独立于前端项目目录，避免被站点发布覆盖
- **备份**：数据库备份与上传目录备份都应纳入宝塔或系统级备份方案

### 3. 推荐部署形态
#### 首选
- `Directus` 通过 Docker Compose 或独立 Node 进程运行
- 宝塔只负责：站点域名、Nginx 反代、SSL、文件权限辅助管理

#### 不推荐
- 把 Directus 直接塞进现有前端站点目录混跑
- 把上传文件目录放在前端发布目录内部
- 让官网前端直接读取宝塔后台内部管理接口而不做只读适配

### 4. 推荐目录与边界
- Directus 服务目录：`/srv/mintbio/directus/`
- 上传目录：`/data/mintbio/directus/uploads/`
- 备份目录：`/data/backup/mintbio/directus/`
- 官网前端目录与 CMS 目录保持分离

### 5. 推荐执行阶段
1. 盘点现有宝塔环境与站点关系
2. 为 `cms` 或测试域名建立站点/反代入口
3. 准备 Directus 服务与独立数据库
4. 配置上传目录与访问路径
5. 建立新闻模型、角色、权限
6. 迁移历史数据与媒体
7. 输出官网只读接口
8. 切换前端数据源
9. 验证、回滚预案、交接运营

### 6. 每阶段最低验证项
- **环境阶段**：域名、端口、反代、数据库连接可用
- **后台阶段**：可登录、可新建新闻、可上传媒体
- **媒体阶段**：上传后经 CDN 可访问，且不触发前端重编译
- **读接口阶段**：列表、详情、分类接口返回稳定
- **切流阶段**：首页、列表、详情均读取新源，旧源可回退

### 7. 宝塔环境下的常见风险
- 在宝塔中误改现网站点配置
- 上传目录权限不足，导致媒体写入失败
- 数据库混用，导致备份和回滚困难
- CDN 缓存未刷新，导致新资源或新内容显示异常
- 把后台管理域名直接暴露在主站路径下，增加安全风险

### 8. 建议优先级
- 优先保证目录隔离
- 优先保证数据库隔离
- 优先保证反代与 HTTPS 独立
- 优先保证回滚开关存在
- 最后再优化编辑体验细节
